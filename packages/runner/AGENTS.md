# packages/runner — ada-runner

**Workspace UI boundary (2026-08-24):** the Buzz-parity work does not move model execution into the SPA/server. Agent creation and token rotation now happen in the UI and return a one-time `setupCommand`; this process still connects outbound with that token and keeps provider access in its own environment. Deactivation or deletion revokes the server-side connection. Card/module/report behavior remains available to conversation publications even though their dedicated pages are no longer mounted (`DECISIONS.md` §21).

**Today:** working, two runtimes: `claude` (real model) and `scripted` (no model; the demo default — `DECISIONS.md` §18). `src/cli.ts` (run with `npm run runner` from the root, or `tsx packages/runner/src/cli.ts --cwd data/<course>/agents/<agent> --token <token> [--server http://localhost:8787] [--model <id>] [--timeout 180]`): connects outbound to `/ws/runner?token=`, announces presence (`online` / `thinking` / `publishing`), and on each `agent.mention` — handled in series — builds a prompt (channel, who, last messages, the question), spawns `claude -p … --output-format json --permission-mode acceptEdits --allowedTools Read,Write,Edit,MultiEdit,Glob,Grep --add-dir <course>/raw` with `cwd` in the agent's folder, snapshots `wiki/**/*.md` before and after (everything except `index.md`/`log.md`), publishes what changed as cards (`card.publish`; frontmatter `type` topic/question/difficulty → note/answer/note), keeps the path → card id map in `<agent>/.ada/cards.json` (gitignored), turns `[[path]]` into `cite` blocks, flattens chat markdown to plain text blocks, posts the answer with `fromCard` when nothing changed in `wiki/` and there's a citation, and makes one git commit per run inside the agent folder when that folder is its own repository (inside another repository — this monorepo's `data/` — runs aren't committed separately, so the seeded wiki stays visible to the outer repo). Self-mentions (the agent's own messages) are ignored. The snapshot fetch sends the agent token as a Bearer header (a gated server — `DECISIONS.md` §20 — requires it; an ungated one ignores it), and before an `ingest` runs, the runner downloads the mentioned module's materials it lacks into its local `raw/` from `GET /api/modules/:id/materials/:mid/raw` — server and runner no longer share a disk when the course is deployed; files already present are never re-downloaded, so same-machine dev is unchanged. Measured on the demo laptop: a greeting answers in ~15 s, a question that writes a card in ~40 s.

**`scripted` runtime** (`src/runtimes/scripted.ts`, selected with `--runtime scripted` or `ADA_RUNTIME=scripted`; `npm run dev` uses it unless `ADA_RUNTIME=claude`): on each mention it pauses 1.2–2.5 s ("thinking", seeded on the message id so reruns look the same), refreshes the community snapshot and picks an intent — `ingest` (an upload-triggered mention, or text with "ingest": splits the module's latest material on `## ` headings, writes one `topic` card per section under `wiki/modules/<module>/`, answers listing them, then sends `module.suggest` with a level chosen from the material plus cohort evidence from the feedback), `plan` (a student asking how to get ahead / prioritize in a module, or any such question in a private channel: a numbered plan citing the module's cards starting from the student's feedback gap, written as a `question` card, then `report.create` for the teacher and a note in `#teachers`), `question` (anything else: the best-matching card by title/body words, or an honest "I checked … and don't have a card on that yet"). It never invents a citation: `[[path]]` only for cards in the snapshot or written in the run. Seeded cards resolve by `path` from the snapshot. Frontmatter `channel:` on a card decides where it's published (default: the mention's channel).

`npm run check:scripted -w @ada/runner` (`scripts/scripted-check.ts`) asserts the scripted runtime against a synthetic snapshot: intent detection, the cards each intent writes, citations only of existing/written cards, the report payload and the `#teachers` note, and the deterministic thinking delay.

Not done: `codex` / `pi` adapters (the CLI refuses `--runtime` other than `claude`), `ingest` is only a prompt convention, no `commander` (a tiny arg parser), no `templates/` — the agent's rules live in `data/<course>/agents/<agent>/CLAUDE.md` (copied as `AGENTS.md`).

**What it will be:** the process that makes an agent exist. It connects *outbound* to the server with the agent's token (`/ws/runner?token=`), receives mentions, runs the chosen **runtime** with `cwd` set to the agent's folder, turns `[[path]]` citations into cards, publishes the new/changed `.md` files under `wiki/`, and makes one commit per run. Runtimes: `claude` (built), `codex` and `pi` (same interface, untested). **Never asks for or stores AI credentials**: that's the provider binary's job (rules verified in `research/2026-08-22-subscriptions-runners-buzz-pi.md`).

**How it grows (idea, not code):** run on each student's machine (personal agent), on the teacher's Railway instance (`claude setup-token`), or on our hosting with API keys and open models via `pi` — without touching the server or client (`DECISIONS.md` §14, `docs/como-funciona.html`).
