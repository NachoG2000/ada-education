# apps/web — the web client

**Today:** Ada's most complete piece. A Vite + React 19 SPA that by default runs **connected**: `.env` sets `VITE_ADA_SERVER=/`, which rides `vite.config.ts`'s dev proxy into `apps/server` (no CORS needed; an absolute URL works too). `npm run dev:demo` clears it and runs the synthetic community in `src/lib/demo.ts` with a frozen date (`NOW` in `App.tsx`). Connected: `src/lib/api.ts` is the client — REST for reads and posts, WS for `/ws` events, and a reducer that folds each event onto the snapshot, tolerant of unknown event types or ids: `sanitizeSnapshot` cleans the hydration snapshot and `degradeMessage` cleans every incoming message, so a reference the client can't resolve (a `fromCard` for a card that isn't here, a citation, a thread) is degraded away with a warn — the seal disappears, the citation goes back to being its text — and only a message with no author or no channel is dropped, rather than feeding `CommunityProvider`'s throwing lookups a dangling reference. Whatever still throws is caught by `components/ada/boundary.tsx`, which is wrapped around each message row, the contextual panel and the whole app: never a blank page. With no stored identity, `components/ada/who-are-you.tsx` asks who you are and keeps the choice in `localStorage["ada:me"]`. `Composer` (`components/ada/channel.tsx`) posts over REST with `@`-mention autocomplete and a notice when a mentioned agent's runner is disconnected; a message with no thread offers a quiet "Reply in thread" that opens one with `POST /api/threads` (the server doesn't mark the root message, so `api.ts` sets the root's `threadId` itself — that's what makes the thread reachable); the member list, thread header and agent sheet show live `Presence` plus the runner's runtime/model from `member.presence`; cards and their "already on file" seal update live from `card.published`. Chat-app behavior: every WS open (the first one and every reconnect), the tab coming back in front and the network coming back trigger a resync (`GET /api/community` replaces the snapshot, runner info kept) so nothing posted while the socket was down is lost; a channel you aren't looking at gets an unread mark when someone else writes there (cleared on open, count in the tab title); the last channel is remembered in `localStorage["ada:channel"]`. `api.ts` still mirrors the event types by hand — `@ada/protocol`'s `events.ts` already exists and task 1.4b is marked done, but `api.ts` hasn't switched over to importing from it yet, so `ServerEvent` lives in two places for now. With `VITE_ADA_SERVER` empty none of this runs and the SPA is exactly the demo it always was.

No router (`location.hash`, subscribed to `hashchange` so `#figures` switches an already-open tab), a single context (`lib/community.tsx`), product components in `components/ada/`, shadcn primitives in `components/ui/`, "The card file" design system in `index.css` (named rules in `DESIGN.md`: Tab Rule, One Sun Rule, Three Voices). Domain types live in `@ada/protocol` (`src/lib/types.ts` only re-exports). Full detail in the root `AGENTS.md` → Architecture section.

**Local production:** on the teacher's machine the intended setup isn't `dev:web` + `dev:server` side by side — it's `apps/server` serving `apps/web/dist` itself, same-origin, one process and one port. Not built yet; goes in `apps/server`.

**Modules and study (2026-08-23, DECISIONS.md §16):** the hash also carries two role screens, independent of the contextual panel — `#modules` (teacher, `screens/Modules.tsx` → `ModulesScreen`) and `#home` (student, `screens/Study.tsx` → `StudyScreen`); anything else is the channel screen. `screens/Channel.tsx` reads `view` from the context and gates by role at the top of the component: a student on `#modules` or a teacher on `#home` gets `location.replace`d to their own screen (in an effect), and the safer screen (home) renders in the meantime so the wrong role never even flashes the other one. The contextual panel (`PanelStack`) is shared unchanged by all three. `useCommunity()` grew: `view` (`"channel" | "modules" | "home"`, from the hash via `useSyncExternalStore`); `showChannel(id)` (switches to the channel screen and shows this channel, clearing the hash without a history entry); `goTo("modules" | "home")`; `switchPerson()` (forgets `localStorage["ada:me"]`, reloads into the picker); the REST wrappers `uploadMaterial(moduleId, input)`, `patchModule(moduleId, input)`, `reconcileReport(reportId, input)` (reject in demo; `useConnectedCommunity` adds `authorId` from the local identity when connected — mirrors `sendMessage`); `moduleCards(moduleId)` (a module's cards, oldest first, base docs excluded); `myFeedback()` (feedback addressed to me, newest first); `presenceOf(memberId)` (a member's live presence, `"away"` for an id that doesn't resolve). `AppSidebar` puts the role's landing entry (`RoleEntry`: "Modules" for a teacher, "My study" for a student) above the Course drawer, routes channel clicks through `showChannel`, lists a private channel only to its own members, and the footer member button is a real `<button title="Switch person">` wired to `switchPerson`. `Composer` (`components/ada/channel.tsx`) gained `channelId` (target channel, defaults to the active one — lets it post outside the open channel, e.g. the student's private channel from the study screen), `suggestions` (a row of pill chips above the field; clicking one fills the field and focuses it) and `autoFocus`.

Local rules: don't touch `components/ui/` unless necessary (prefer composing in `components/ada/`); a broken id in `demo.ts` still takes down the row or panel that uses it (the lookups throw; the boundaries only keep it from taking down the app); the contextual panel is a stack of at most two of `thread | card | agent` (`Panel` in `lib/community.tsx`) — the agent sheet opens from the members drawer, the thread header or a card's author; everything in English.
