## Why

Teachers should create an agent by naming it and writing rules, then immediately use it. Per-agent provider selection and runner enrollment interrupt local product iteration and should be installation concerns.

## What Changes

- Replace the mounted creation/setup flow with name, rules, and channels plus two editable classroom templates.
- Create tutor and curator starter agents with UI-created communities.
- Start an installation agent host with the development command; automatically enroll, restart, serialize model work, and stop agents.
- Keep provider authentication local by default; allow explicit API-key mode for a future deployed installation.
- Preserve agent memory, tenant boundaries, deletion history, and the external runner topology.

## Capabilities

### New Capabilities
- `automatic-agent-host`: Installation-scoped enrollment, process lifecycle, and authentication configuration.

### Modified Capabilities
- `web-client`: Agent creation and editing without provider or enrollment setup.

## Impact

Web agent dialogs/details, community creation, server enrollment, shared templates and schemas, runner lifecycle, development startup, and their checks/docs. No SDK migration or hosted deployment in this change.
