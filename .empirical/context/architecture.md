# Architecture

Maintained from repository evidence (verified 2026-08-23 against the files named below).

## Components and ownership

- `apps/web/` — Vite + React 19 + Tailwind v4 + shadcn (Base UI) SPA. No router: `src/App.tsx` picks the screen from `location.hash` (`#figures` → `FigureSheet`; otherwise `ChannelScreen`). Runs connected by default (`apps/web/.env` sets `VITE_ADA_SERVER=/`, proxied to the server); `npm run dev:demo` uses the synthetic community in `src/lib/demo.ts`.
  - State = one context: `src/lib/community.tsx` (`CommunityProvider` / `useCommunity()`): `community`, `now`, `mode`, `me`, `connected`, `sendMessage`, `replyInThread`, `runnerInfo`, `activeChannelId`, `panels` (right-hand stack, max 2: thread | card | agent), `openThread/openCard/openAgent/closePanel/popPanel`, lookups `member/card/thread/message` that **throw** on unknown ids.
  - Connected client: `src/lib/api.ts` (`GET /api/community`, `POST /api/channels/:id/messages`, `POST /api/threads`, WS `/ws` with reconnect; `applyEvent` reducer).
  - Screens: `src/screens/Channel.tsx` (the whole product: shadcn inset sidebar + two resizable panels). Product components in `src/components/ada/` (folder, channel, panel, card, message, identity, markdown, who-are-you, boundary); shadcn primitives in `src/components/ui/`.
  - Identity: `WhoAreYou` picker → `localStorage["ada:me"]`; "Switch person" in the sidebar footer clears it. `Person.role` gates two views of the same shell: `#modules` (teacher: `screens/Modules.tsx`, `components/ada/modules.tsx`) and `#home` (student: `screens/Study.tsx`, `components/ada/study.tsx` + `study-helpers.ts`); `Channel.tsx` redirects a wrong role. `useCommunity()` exposes `view/goTo/showChannel/switchPerson/uploadMaterial/patchModule/reconcileReport/moduleCards/myFeedback/presenceOf`.
- `apps/server/` — Hono on `node:http` + SQLite (`node:sqlite`, schema `src/schema.sql`: community, members, channels, channel_members, messages, threads, cards, modules, materials, assignments, feedback, reports). Routes in `src/api.ts` (`GET /api/community`, `POST /api/channels/:id/messages`, `POST /api/threads`, `POST /api/cards`, `POST /api/modules/:id/materials` (teacher-only 403 gate, name sanitized against traversal, writes `raw/<teacherId>/modules/<id>/<name>`, status `compiling`, posts `@ada ingest …` with the `ingest` hint), `PATCH /api/modules/:id` (teacher-only), `POST /api/reports/:id/reconcile` (teacher-only; publishes a `decision` card)); WS hub in `src/ws.ts` (`/ws` broadcast: message.created, thread.created, card.published, member.presence, module.updated, feedback.created, report.updated; `/ws/runner?token=`: agent.mention (+ intent/moduleId), presence, message.create, card.publish, module.suggest, report.create). Mentions (`src/mentions.ts`): `@id` in text, plus every person's message in a `private` channel; forwarded live with ≤20 context messages; dropped silently if no runner is connected. Seed: `src/seed.ts` loads `data/<course>/community.json` (`ADA_COURSE`, DB path `ADA_DB`) idempotently, including `modules/assignments/feedback/reports/messages` (`ago` shorthand, `[[path|label]]` cites) and `wikiCards: true` (every `agents/ada/wiki/**/*.md` becomes a card with id `card:ada:<path>`).
- `packages/protocol/` — shared domain types (`src/types.ts`: Person, Agent, Card, Message with `paragraphs: MessageBlock[][]`, Thread, Channel, Community) and Zod event schemas (`src/events.ts`: `ServerEvent` = message.created | thread.created | card.published | member.presence; runner messages `agent.mention`, `presence`, `message.create`, `card.publish`, `ack`). `apps/web/src/lib/types.ts` re-exports it.
- `packages/runner/` — two runtimes behind one pipeline. `claude`: spawns `claude -p <prompt> --output-format json --permission-mode acceptEdits --allowedTools Read,Write,Edit,MultiEdit,Glob,Grep --add-dir <raw>` in the agent's folder. `scripted` (`src/runtimes/scripted.ts`, the `npm run dev` default via `ADA_RUNTIME`): 1.2–2.5 s "thinking", intent `ingest` (material headings → topic cards + `module.suggest`), `plan` (feedback gap + module cards → numbered plan card, `report.create`, note in `#teachers`), `question` (best-matching card or an honest miss). Both: diff `wiki/**/*.md` before/after → `card.publish` (frontmatter `channel:` picks the channel), `[[path]]` → cite (seeded cards resolve by `path` from the snapshot), "from the file" seal, after-actions. One git commit per run only when the agent folder is its own repository (inside this monorepo it isn't committed separately).
- `data/<course>/` — the course: `community.json` (seed: people, channels incl. `teachers` and private `<student>-ada`, modules 01–04, assignment, feedback ×3, one reconciled report, 14 messages), `raw/<teacher>/modules/<nn>-<slug>/*.md` (material), `agents/<agent>/` (the agent's `CLAUDE.md`, `wiki/` = its memory: `modules/<id>/*.md`, `decisions/`, `questions/`, `index.md`, `log.md`).

## Data and control flow

1. Web loads the snapshot (`GET /api/community`), opens `/ws`, and applies events through `reduceLive`.
2. A person posts (`POST /api/channels/:id/messages`) → server stores → broadcasts `message.created` → scans `@mentions` → sends `agent.mention` to the connected runner.
3. The runner runs the provider binary in the agent's folder, publishes changed wiki files as cards (`card.publish` → `card.published`) and posts the answer (`message.create` → `message.created`, with `fromCard` when it only cited existing cards: the "already on file" seal).
4. Teacher/student flow (`DECISIONS.md` §18): upload material → `module.updated` (compiling) → ingest mention → cards + `module.suggest` (ready, suggested difficulty; the teacher's hand-set level wins) → student asks for a plan in her private channel → plan message + plan card + `report.create` + `#teachers` note → teacher reconciles → `decision` card + `report.updated` + module `revision`.
5. Cards are immutable by convention: a contradiction creates a new card with `supersedes`/`replaces`; the UI shows `new | updated | superseded | compiling`.

## External dependencies

- Runtime: Node 24 (`node:sqlite`), npm workspaces. Web: react 19, vite, tailwind v4, shadcn/Base UI, lucide, react-resizable-panels. Server: hono, zod. Runner: the `claude` CLI installed and logged in (credential lives with the binary, never in Ada — `DECISIONS.md` §14).
- No external services, no auth provider, no database server. No tests framework is installed.
